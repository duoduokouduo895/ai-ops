# Stage 5.2 实现与云端发布验证记录（2026-07-13）

## 结论

Stage 5.2 的本地实现和私有云端发布已完成。AI-chat candidate `20260713-stage5-candidate-13`、AIDiag release `20260713-stage5-diagnosis-1`、4 条告警规则和 Grafana Dashboard 已运行；Alertmanager 合成告警已验证自动建单、持久化任务、确定性证据不足报告与 resolved 生命周期。

当前仍不能声称四类规则已有线上准确率，也不能把“真实 Metric + Log 联合证据”门禁标记为通过。该门禁需要 Stage 5.3 在隔离实例中逐类制造真实故障，不能用合成告警或真实用户实例冒险代替。

## 实现范围

- 将原 `RuleBasedDiagnosisService` 内的 Fault Lab `switch` 拆为 `DiagnosisRuleRegistry`、`FaultLabDiagnosisRuleProvider` 与 `AiChatDiagnosisRuleProvider`；注册表以精确 `(serviceName, alertName)` 查找，未知或注入式值不会执行任何遥测查询。
- 保留 4 条 Stage 3 Fault Lab PromQL 与判断阈值，并新增 `AiChatModelTimeout`、`AiChatR2dbcPoolExhaustion`、`AiChatDocumentBacklog`、`AiChatSearchUnavailable`。
- 每条 AI-chat 规则固定 PromQL、LogQL、TraceQL、阈值、Ground Truth、候选根因与只读 Runbook action。告警 label 和 annotation 不参与查询拼接。
- AI-chat 新增 R2DBC pool 低基数 Gauge、文档 outbox pending Gauge、搜索 outcome Counter，以及 R2DBC 获取超时、文档投递重试、搜索结果的脱敏运维事件；事件不包含 Prompt、查询文本、SQL、用户/会话 ID 或异常正文。
- Tempo collector 单次最多接收 50 条有效 traceId 摘要，HTTP 响应最多 128 KiB，工具超时最多 10 秒；只保存 traceId 和 duration，不保存 root span 名称、完整 Span 或属性。
- Grafana Dashboard 按“抓取状态 -> 活跃流/超时/TTFT -> 容量与积压 -> 结果趋势 -> 脱敏事件”组织。缺失 series 明确表示证据不足，不解释为健康的 0。

## 判定边界

- 只有 Metric 与 Log 两类 P0 证据同时命中才返回 `SUPPORTED` 并允许写入主要根因。
- Trace 只增加佐证分；Tempo 超时、不可用、超大响应或无结果不阻断 Metric/Log P0 报告。
- Metric 或 Log 任一缺失时最多为 `WEAKLY_SUPPORTED`，不得写入主要根因。
- Ground Truth 仅用于 Stage 5.3 隔离故障实验评测，不代表生产告警一出现就已确认根因。

## 数据源与指标口径

| 面板/规则 | 来源 | 口径与限制 |
|---|---|---|
| 模型超时 | `aichat_chat_requests_total{outcome="timeout"}` + `ai_chat_stream_finished` | 5 分钟至少 1 次；只表示流按超时分类结束 |
| R2DBC Pool | `aichat_r2dbc_pool_pending` + `r2dbc_pool_acquire` | pending 至少 1 且出现获取超时事件才确认；PoolMetrics 不可用时保持证据不足 |
| 文档积压 | `aichat_document_outbox_pending` + `document_outbox_dispatch` | pending 来自数据库刷新与进程内增减；候选禁用后台任务时只作为被动状态，不制造故障 |
| 搜索不可用 | `aichat_search_requests_total{outcome="error"}` + `knowledge_search` | 5 分钟至少 3 次未降级错误；索引不存在并安全降级为空不算不可用 |
| Trace | Tempo 固定 TraceQL | 最多 50 条紧凑摘要；不可作为单独确认根因的依据 |

## 云端发布结果

1. AI-chat candidate 保持非 root `10001:10001`、只读根文件系统、0 重启，仅绑定 `127.0.0.1:18082/19091`；Flyway、RabbitMQ listener/动态声明、调度、ES 同步、Nacos discovery、健康探测任务和模型预热保持关闭。
2. AIDiag 仅重建 `aidiag-backend`、Prometheus 和 Grafana；未修改 DNS/Nginx，未重建 Alertmanager、Loki、Tempo、Alloy 和 Fault Lab。
3. 隔离测试首次启动时，Compose 因 `depends_on` 和 release 路径变化意外重建了 PostgreSQL 容器。持久卷未删除，生产库计数保持 20 Incident / 20 run / 3 历史活跃 Incident，AIDiag 后端保持健康且未重启；后续测试命令必须显式使用 `--no-deps`，避免再次扰动数据库。
4. 合成告警只用于验证传输、幂等建单、任务和 resolved 生命周期，不作为真实诊断准确率样本。四类真实 Metric/Log 联合证据与 Trace 降级评测留到 Stage 5.3 的隔离故障实验。
