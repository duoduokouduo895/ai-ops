# Stage 5.3 隔离故障实验验证记录（2026-07-13）

## 结论

Stage 5.3 的隔离 contract lab 已完成。`ai-chat-stage5-lab` 在不连接真实 AI-chat 数据库、中间件和模型 Provider 的条件下，对模型超时、R2DBC 获取等待、文档 outbox 积压和搜索不可用四类遥测契约各执行 5 轮，共 20 个生命周期。20/20 自动建单、20/20 生成 `SUPPORTED` 报告、20/20 恢复为 `RESOLVED`。

本结果证明 AIDiag 的告警、聚合、持久化任务、多信号证据、确定性报告和恢复链路可以重复运行；它不证明真实 AI-chat 依赖故障的生产准确率。

## 隔离与安全边界

- 实验服务仅加入 `aidiag-faultlab` 与 `aidiag-telemetry` 网络，无 host port，不加入 AI-chat 或 AIDiag 数据库网络。
- 容器使用 `10001:10001`、只读根文件系统、独立 32 字节以上 Secret；缺失或错误 Token、未知路由统一返回 404。
- 故障控制只改变实验指标、脱敏日志和 Trace，不调用真实 MySQL、RabbitMQ、Elasticsearch、Redis、Nacos 或 DeepSeek。
- 结束时 4 个故障 gauge 均为 0；容器 `healthy`、重启次数 0、host port 为空。
- 动态检查最近 92 条实验日志，未发现 Prompt、回答、用户/会话标识、Authorization、API Key、Secret 或查询正文等字段。

## Stage 4 联动

在最后一轮已恢复的 Incident 上手动调用一次 DeepSeek 预览：

- 返回 `COMPLETED`；
- advice 引用 3 条既有 evidence；
- `automatedRemediation=false`；
- 当日请求预算只增加 1；
- 调用前后确定性 `report_json` 的 SHA-256 相同。

DeepSeek API 响应和当前审计表只能确认调用次数与 token 边界，不能直接取得人民币或美元的实际扣费，因此“实际货币费用”仍是未测量项，不能填写估算值冒充账单。

## 失败样本与修正

1. 首次发布因 release 解压目录权限继承过严，Prometheus 无法读取配置；健康门禁回滚到 Stage 5.2。修正为目录 `755`、普通文件 `644`、脚本 `755`，Secret 保持 `640`。
2. 首轮验收已生成报告，但脚本用无空格字符串匹配 JSON，误判为未完成。修正为 Python JSON 解析，不再依赖序列化空格和字段顺序。
3. 第二轮 20 个生命周期均通过，但最终哈希检查错误依赖未安装的 PostgreSQL `pgcrypto.digest()`。未给数据库新增无必要扩展，改为读取报告后使用系统 `sha256sum`。
4. 仅更新验收脚本时，旧发布脚本显式执行 `docker compose down`，造成默认栈被重建。已删除显式 `down`，改为 `up -d --remove-orphans --wait`；未来变更服务仍可能按 Compose 配置重建，但不再无条件先停止整个栈。

这些失败属于发布和验收工具问题，不计入诊断准确率样本；它们必须保留记录，不能只归档最终成功结果。

## 遗留门禁

- contract lab 没有真实破坏 AI-chat 依赖，不能据此宣称生产准确率或 100% 诊断率。
- 5 轮的查询窗口可能重叠，样本不是统计独立样本；Stage 5.4 应按非重叠窗口收集 shadow 数据。
- 尚未测量长时间误报率、真实漏报率、弃权率、峰值并发和 Tempo/Loki 长时间不可用时的恢复表现。
- 正式切流前仍需完成 Nacos 匿名访问与历史 Secret 轮换、Incident API 鉴权/分页/审计，以及 DNS/Nginx 变更评审。
- 自研前端应扩展现有 `frontend_admin`，浏览器不得持有 AIDiag Operator Secret；先设计只读 Incident/报告 BFF，再考虑页面实现。
